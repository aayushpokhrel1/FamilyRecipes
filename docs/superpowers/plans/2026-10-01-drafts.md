# Drafts (5a): implementation plan

Spec: `docs/superpowers/specs/2026-10-01-drafts-design.md`. Read it first; the decisions there
are settled.

Order matters: the migration reaches cloud BEFORE the frontend that needs it, as always.

## Task 1: migration 0033, `recipe_drafts`

The table exactly as the spec prints it, plus RLS with four policies all keyed on
`author_id = auth.uid()`, and an `updated_at` touch on update (mirror whatever 0008 does for
meal plans rather than inventing a second idiom).

Integration tests in `tests/integration/recipe_drafts.test.ts`:
- a cook can insert, list, update and delete their own draft;
- **another cook in the SAME family cannot see it**, which is the whole ownership decision and
  the test most worth having;
- an anonymous client cannot read any draft;
- `target_family_id` and `title` are both `not null` and rejected when missing.

## Task 2: `src/lib/api/drafts.ts`

All Supabase access lives in `src/lib/api/`. Exports, with `SavedDraft` added to `types.ts`
alongside the existing `RecipeDraft` (which keeps its meaning, form state):

- `listDrafts(): Promise<SavedDraft[]>` newest first
- `getDraft(id): Promise<SavedDraft>`
- `saveDraft(draft: RecipeDraft, familyId: string, visibility, id?: string): Promise<string>`
  inserts when `id` is absent, updates when present, returns the id
- `deleteDraft(id): Promise<void>`

The loader must tolerate a `body` missing any field (see the ceiling in the spec) and fill
defaults rather than throwing. Unit tests in `src/lib/api/drafts.test.ts` mirroring the style
of the existing api tests, including the missing-field case.

## Task 3: the UI

- `RecipeCreate`: a **Save draft** button beside Save, disabled without a title with the
  reason beside it. Saving from a form that was loaded from a draft updates that draft.
- `/drafts`: a page listing drafts with Resume and Delete, and a route for it.
- The Recipes page links to `/drafts` only when at least one draft exists.
- Resume prefills the create form; publishing creates the recipe and THEN deletes the draft,
  never the other way round.

## Task 4: verification (not delegated)

`npx supabase db reset`, `npx tsc -b`, `npm test`, `npm run test:int`, then a browser pass on
a fresh account: save a draft, close the page, resume it, publish it, confirm the draft is
gone and the recipe exists. Tests have missed this class of bug three times in this project.
